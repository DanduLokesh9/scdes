AI Governance

How it works

The front end and the back end, in plain language.

app.staging.governingai.us  ·  August 2026

The problem

An agency writes its AI rules down.
Then they sit in a binder.

Several hundred pages: a framework, an operations manual, fourteen appendices.

Somebody wants to build an AI tool. Which rules apply? What risk band? Who approves it? Which forms?

In practice nobody reads it. The rules get applied from memory, inconsistently — and the record of why a decision was made is a scattering of emails.
2

What we built

Software that reads the rules
and then runs them

It answers questions

"What triggers a Level 2 incident?" — with the exact section cited. And it refuses questions the documents don't cover.

It scores risk

Using the agency's own six factors and weightings — and shows what would change before anything is saved.

It keeps the record

Every action written down, including every refusal, in a chain where tampering shows.

Nothing about the rules is written into the code. Point it at a different agency's documents and it becomes that agency's application.
3

The shape of it

Two halves

Back end — the server

Reads the documents. Does all the thinking: risk scoring, searching, permissions, record-keeping.

Python · 24 files · ~7,300 lines

Front end — the browser

Everything you see and click. Holds no rules of its own — it asks the server for everything and draws the answer.

HTML, CSS, JavaScript · 8 files · ~3,000 lines

Why the split matters. All the judgement lives in one half. The browser cannot decide a project is Low risk — it can only display what the server said. Tampering with the page changes what you see and nothing about the record.

Part one

The back end

The half that reads, thinks, and remembers.

Back end · reading

Teaching software to read a spreadsheet

A human sees "Project Name:" and a box to write in. A computer sees two cells.

  • The reader recognises four shapes these documents use over and over: a form, a checklist, a table of weightings, a table of records.
  • Result: 1,068 individual fields found across 14 workbooks — each one knowing which file, sheet and cell it came from.
  • Appendix G literally says [Select: Water / Land and Waste / Air]. The software reads that hint and builds a dropdown with exactly those three options.
Nobody typed those options into the code. Amend the appendix to add a fourth programme, and the dropdown gains a fourth option. No developer needed.

Back end · thinking

The feature that sells it

The risk calculation changes nothing. It takes numbers in and gives an answer out — no saving, no side effects.

Which means the same code can safely be run against hypothetical settings.

If you move Data Sensitivity from ×1.5 to ×2.0:

  → 2 projects move from Moderate to High
  → a Council decision is newly required at Gate 2
  → Appendix K becomes mandatory for both
Shown before anything is saved. "Exploring changes nothing" becomes structurally true, rather than a rule someone has to remember not to break.

Back end · honesty

One gate, not fifty

Every action that changes anything passes through a single function that asks two questions: who are you, and what mode is the agency in.

  • It records its answer either way — permission granted and permission refused both go into the log.
  • The test suite actively attacks it: it tries to make the chat assistant edit settings, an operator move a risk weight, a what-if overwrite the real budget. Each must be refused and the refusal logged.
Why one place. If every screen checked permissions for itself, there would be fifty chances to forget one.
9

Back end · honesty

The audit trail

Every entry carries a fingerprint of the entry before it.

Like a ledger where each page prints a summary code of the previous page. Tear out page 40 and page 41 no longer matches page 39 — the gap is obvious even though the page is gone.

What it does not do. It is tamper-evident, not tamper-proof. Someone with file access could rewrite the whole chain from the beginning and it would verify cleanly. Closing that needs a write-once store or digital signatures. We are saying so rather than letting it be assumed.

Front end · theming

Each agency's own colours

Pick a state and the whole interface takes on that agency's identity — harvested from its live public website.

What went wrong first

Every agency was forced into a fixed set of eight colours, with the gaps generated. Each looked fine alone — but the filler followed the same recipe every time, so all fifty states drifted toward looking identical.

What it does now

However many colours an agency actually has — 2 to 19 — and no padding. A three-colour agency is themed in exactly its three.

Risk colours never change. Low green, Moderate amber, High red — in all fifty states. A record where "High risk" is maroon in one state and olive in the next invites misreading.

Putting it together

What happens when you click "Registry"

1. Browser      asks the server for the project register
2. Server       works out who is asking
3. Permission   may this person see it?          yes
4. Data         reads the project records from disk
5. Thinking     works out each project's risk band
6. Wording      labels them in the agency's own terms
7. Answer       sends back a plain data message
8. Drawing      the browser turns it into the table you see
Steps 3 to 6 are all on the server. The browser receives finished answers — never the rules that produced them.

The three libraries are all for reading documents: Excel, Word, and settings files. The web server is Python's own.

Why so few. Every framework added is something that must be kept updated for as long as the record must be readable — and a governance record outlives most frameworks. This can be picked up in five years and still run.

Being straight about it

What is real, and what is not

Real

  • The adopted SCDES documents, parsed
  • The risk weights, read from Appendix B
  • The integrity findings — 1 critical, 2 serious, 10 moderate
  • The map geography and the state flags

Not confirmed

  • No agency has approved the scraped colours
  • Agency names are seeded and marked unverified
  • Budget weights and roadmap costs are placeholders
  • Only one agency's documents load at a time
Before this URL is shared: there is no log-in security yet. Anyone with the address can currently act as the Council.
